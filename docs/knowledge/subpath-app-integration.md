# 子路径应用集成纪律

本站以「根路径双语首页 + 每个应用一个子路径」的方式组织。接入新应用、或把现成官网整站迁入子目录时，适用以下稳定做法。

## 相对路径纪律（子路径安全）

- **场景**：任何页面要挂到站点子路径下，或判断页面改动是否部署安全。
- **症状**（违反时）：页面在根路径预览正常，挪到子路径部署后样式 / 图标 / 链接 404。
- **原因**：页面内使用根绝对路径（`/assets/...` 形式）或写死绝对域名，挪到子路径后解析到站点根，资源落空。
- **做法**：页面内资源引用与互链一律用相对路径（同层直接写、跨层用 `../`）；允许的例外只有指向外部服务的链接（如应用商店外链）。双语镜像页面互切同理：英文页回中文页用 `../`。交付前自检：全站页面无根绝对路径引用 ⇒ 任意部署根（根路径 / 子路径 / 本地服务）都能工作。

## 快照迁移校验

- **场景**：把已有官网仓库原样迁入子目录，此后只在本站仓库维护该应用页面。
- **症状**（不做校验时）：迁移过程混入无意识的改写，日后与源站比对无从判断差异来源。
- **做法**：复制时排除源仓库的 `.git`、`CNAME`、`.nojekyll`——域名与 Pages 开关只属于站点根，子目录残留会让 Pages 域名识别与构建行为异常；迁移完成后用 `diff -r` 按同一排除清单逐字节比对源快照，确认零改写。

## 新应用接入流程

- **场景**：接入一个新应用的 Homepage。
- **做法**：照仓库根的接入文档 `ADDING-AN-APP.md` 四步走——建子目录、放图标、双语首页登记卡片（照抄文档模板，与首页实际标记一致）、本地自检。卡片入口路径：中文页写 `应用目录/`，英文页写 `../应用目录/`。
